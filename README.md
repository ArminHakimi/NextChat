# NextChat

NextChat is a simple Next.js chat app with live WebSocket messaging powered by Socket.IO.

## What It Includes

- A custom Next.js server in `server.mjs` that hosts Socket.IO
- A single-room chat UI at `/`
- Live message broadcast for all connected clients
- Editable display name and lightweight room presence events

## Run Locally

```bash
npm install
npm run dev
```

Open `http://localhost:3000`.

To verify realtime behavior, open the app in two browser tabs and send messages from one tab to the other.

## Single-password access

Set `APP_PASSWORD` and `APP_AUTH_SECRET` in `.env.local` to protect the app with one shared password. Generate the secret with:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Use a strong, unique password and keep both values private. The password gate protects app pages, API routes, and Socket.IO connections. Sessions use an HTTP-only cookie and expire after 30 days. In production, the app fails closed if either setting is missing or the secret is shorter than 32 characters. Without these settings, local development remains open.

## Progressive Web App

NextChat can be installed as a PWA. The web manifest is served from `src/app/manifest.ts`, icons are generated by `src/app/pwa-icons/[size]/route.tsx`, and `public/sw.js` caches static assets. It does not cache pages, which may contain authenticated content. The service worker is only registered in production builds (`npm run build && npm start`); in dev mode any existing registration is removed to avoid stale caches. Realtime chat still requires a network connection.

## Voice & Video Calls

Each group has an optional call that anyone in the group can start or join (up to 6 people).

- Media flows peer-to-peer over **WebRTC** (a full mesh); the Socket.IO server only relays signaling (offers, answers, ICE candidates).
- Controls: mute/unmute, camera on/off, leave. Without a camera you join voice-only.
- Everyone else in the group gets a ring banner with a short tone. If the tab is in the background and notifications are allowed, a system notification is shown as well. The browser asks for notification permission the first time you start or join a call.
- Switching groups or disconnecting leaves the call.

Code: `src/lib/useRoomCall.ts` (WebRTC hook), `src/components/CallPanel.tsx` (UI), `src/app/api/ice/route.ts` (ICE server config), and the `call:*` handlers in `server.ts`.

### Requirements

1. **HTTPS**: browsers only allow camera/mic on secure origins. `http://localhost` works for local testing. For other devices, use HTTPS (reverse proxy, or a tunnel such as ngrok / Cloudflare Tunnel).
2. **TURN server** (recommended): STUN alone fails on many corporate and mobile networks. Copy `.env.example` to `.env.local` and set `TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL`, either for a hosted provider (e.g. Metered, Twilio) or a self-hosted [coturn](https://github.com/coturn/coturn). `STUN_URLS` is optional (defaults to Google's public STUN server).
3. **Permissions**: users must allow camera/microphone (and optionally notifications).

## WebSocket Events

- `chat:history`: sends the recent room history to a newly connected client
- `chat:join`: stores the current display name and emits a system join message
- `chat:message`: broadcasts a new chat message to every connected client
- `call:join` / `call:leave`: join or leave the current group's call; the server replies with `call:participants` and notifies peers with `call:peer-joined` / `call:peer-left`
- `call:signal`: relays WebRTC offers, answers, and ICE candidates between two participants of the same call
- `call:media-state`: broadcasts mute/camera changes as `call:peer-media`
- `call:state` / `call:ring`: tell group members how many people are in the call and ring them when a call starts

## Notes

- Message history and call state are kept in memory, so they reset when the server restarts.
- The existing example routes like `/about`, `/users`, and `/api/*` still remain in the project, but the main app experience is now NextChat.
